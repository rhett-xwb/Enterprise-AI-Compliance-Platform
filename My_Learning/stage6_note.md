# 阶段六学习笔记：让系统找到有权限、有版本的制度原文

日期：2026年10月12日  
主题：切片、Embedding、向量数据库、检索过滤与索引重建。

## 1 本阶段目标：先把依据找对

RAG 是“检索增强生成”：先从资料里找依据，再交给生成模型回答。阶段六完成前半段，让系统找到与问题相关、当前有效且用户有权阅读的制度原文。阶段七才负责生成答案和保存引用。

生活类比：公司有一个资料室。第五阶段把扫描纸张变成可读文字；第六阶段把长文件整理成有编号的资料卡，建立查找目录。你问“出差前怎么办”，管理员先找到适用条款，同时检查它是否是现行版、你是否能看。下一阶段才根据资料卡组织解释。

**有什么用**：把“模型能说话”和“系统有依据”分开验证。即使暂时没有生成模型，也能直接检验查出的原文是否正确。

## 2 为什么接在解析后面

```text
阶段四：文件、版本、访问范围
  ↓
阶段五：带真实页码/段落的正文来源
  ↓
阶段六：切片 → 中文向量 → 授权检索 → 核对原文
  ↓
阶段七：基于实际命中生成答案并保存引用
```

切片需要可靠正文，引用需要来源，授权需要账号与文档范围，所以这个顺序有实际依赖。先做索引而没有解析来源，会把“文字从哪来”丢掉；先做生成而没有有效检索，无法验证回答是否符合当前制度。

Java 类比：先定义实体和持久化，再做 Service 查询，最后接 Controller 展示。每一层依赖前一层提供可检验的数据。

## 3 切片：把文件变成能独立查找的资料卡

切片就是把长正文拆成较短的文本块（chunk）。整份文档只有一个向量时，出差、报销、请假等内容混在一起，不利于定位具体条款。

项目规则：

| 规则 | 作用 |
| --- | --- |
| 优先按章节、条款和标题起始分段 | 减少不同主题混在一起 |
| 每块最多 400 个 Java 字符 | 适应当前中文模型输入与来源展示 |
| 长条款在句末或换行附近截断 | 尽量保留完整句子 |
| 长条款相邻块重叠 60 字符 | 给边界附近内容补上下文 |
| 不跨来源制造混合页码 | PDF 页码与 Word 段落可以核对 |
| 保存开始和结束偏移 | 能回到原文精确片段 |

例如“第一条 出差审批……”很长，分成多个块时后一块保留前一块末尾 60 字符；遇到“第二条 报销”开始新主题。Word 的“段落 2”仍是段落，不编造为“第 2 页”。

偏移是 Java String 的 UTF-16 `[start,end)`，阅读代码时可以使用 `source.text().substring(start,end)` 验证块正文。这和给数据库明细行保存主表 ID、序号类似，但这里还有文本位置。

**当前边界**：标题识别采用规则，不是完整语义版面分析；复杂章节跨页传播与表格重建还需要增强。小段落可能形成短块，重叠只发生在较长的同一条款内。

入口：[PolicyChunker.java](../backend/src/main/java/com/enterprise/compliance/document/PolicyChunker.java)。

## 4 Embedding：给文字一个“含义坐标”

Embedding 是把文字转换成一组数字（向量）。相近含义的文字通常有相近向量，因此“报销需要提交什么凭证”可以找到“报销时需要提供发票”，即使字面没有完全一样。

生活类比：资料室不只按文件名称排序，还给每张卡记录它在“出差、报销、请假”等含义空间里的位置。这是类比；实际向量的每一维并不直接对应一个可命名主题。

Java 类比：它像一种专门为相似度比较生成的 `float[]`。普通 Hash 值适合判断相同，不能表达含义接近；Embedding 的作用是比较接近程度，不能当加密结果或准确率证明。

本项目使用：

| 项目 | 本次实现 |
| --- | --- |
| 中文模型 | BAAI/bge-small-zh-v1.5 |
| 向量维度 | 512 |
| 推理 | FastEmbed 0.8.1 + ONNX Runtime 1.31.0，本机 CPU |
| 模型来源快照 | 46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59 |
| 比较方式 | Cosine，相似度排序 |

固定快照有利于复现。模型准备脚本先下载指定文件，正式服务只读取本地快照；运行时正文和问题不发送给外部模型 API。模型下载本身需要网络。

**后续怎么用**：换模型前重新评估召回，并重建全部索引。不同模型即使维度相同，也不能认为向量空间兼容。

入口：[retrieval.py](../ai-service/app/retrieval.py)、[prepare-embedding.py](../scripts/prepare-embedding.py)。

## 5 向量数据库与 MySQL 各管什么

向量数据库存储向量并按相似度查找。阶段六选用 Qdrant Client 1.19.1 的本地持久化模式，无需额外启动 Qdrant 容器。

| 存储 | 保存内容 | 是否决定用户能看什么 |
| --- | --- | --- |
| MySQL | 文档身份、版本、正文、块、角色/部门范围、索引状态 | 是，业务事实来源 |
| Qdrant 本地目录 | 向量、块键、版本/来源/范围快照 | 由 Java 提供已授权键；快照不单独决定权限 |
| 原文件目录 | PDF、DOCX、图片及完整性依据 | 下载仍经 Java 授权 |

Java 类比：向量库像可重建的搜索索引，MySQL 像订单主表。搜索索引命中了一个订单，不等于用户就能读取订单；仍要走业务权限。

范围快照记录“建索引时这张卡属于哪些角色和部门”。权限后来变化时不能继续相信旧快照，所以每次查询都从 MySQL 读取实时关联。

**当前边界**：本地 Qdrant 只允许一个进程独占目录、一个 worker，用于单机演示。候选超过 10000 块会明确拒绝，需要迁移服务端和分页/过滤设计。这个边界不是生产容量承诺。

## 6 一次索引为什么有“代次”

代次就是一次索引尝试的 UUID 标识。它区分当前运行、重试与已经过时的响应。

生活类比：资料室重新编目录时，先发一张“本轮工单”。只有本轮工单全部完成并核对，才能换成正式目录。上一轮工单迟到，不得覆盖新目录。

Java 类比：这和乐观锁的版本号、任务执行令牌以及 CAS 思路有关：更新前先确认“我完成的还是当前这次任务”。项目同时使用制度行锁和运行代次校验。

```text
索引前：PARSED，正文已提取
    ↓ prepare：锁定制度，建立 generation，旧块 INACTIVE
调用内部 Embedding 与 Qdrant
    ↓ complete：校验 generation、模型、全部向量键
同事务保存块 + 运行成功 + 版本 READY
    ↓
法务核对后人工发布
```

索引不会自动发布。对已发布版本重建时，先暂停它的检索；成功后恢复，失败继续不可检索，避免一部分旧块和一部分新块混在一起。

业务重复请求默认复用成功代次；显式 rebuild 才生成新代次。内部相同键 upsert 不追加重复项。外部向量写入成功、MySQL 未完成时，向量虽然存在，却没有有效代次，无法进入业务候选集。

**有什么用**：把两个不同存储间无法使用同一个本地事务的问题，转化为“先准备，再验证启用”。系统不宣称拥有跨 MySQL/Qdrant 的分布式事务。

入口：[IndexStore.java](../backend/src/main/java/com/enterprise/compliance/document/IndexStore.java)、[V6 迁移](../backend/src/main/resources/db/migration/V6__retrieval_index.sql)。

## 7 权限过滤为什么做两次

查询流程：

```text
问题 → MySQL 取当前授权且有效的向量键
     → Qdrant 按这些键过滤，再排序
     → 新事务从 MySQL 再校验权限和版本
     → 取实际正文，返回来源
```

第一次过滤减少无权资料进入检索的机会，并避免无权高分项占满 topK。第二次过滤处理网络调用期间角色、部门、发布版本或有效期已经改变的情况。

实时检查包括：POLICY 知识域、currentVersionId、PUBLISHED、READY、生效时间、失效时间、成功索引代次、有效块、当前角色与部门、用户未停用。管理员能治理全部文档，但制度检索仍按适用范围查询。

Java 类比：方法权限像“能不能进入查询柜台”，资源权限像 SQL 的 WHERE 条件。`@PreAuthorize` 通过后仍必须执行资源过滤，不能仅靠前端隐藏按钮。

**后续怎么用**：阶段七只能用这条链路得到的真实命中构造模型上下文，不能自己绕过过滤重新查全部向量。

入口：[RetrievalStore.java](../backend/src/main/java/com/enterprise/compliance/document/RetrievalStore.java)、[RetrievalController.java](../backend/src/main/java/com/enterprise/compliance/document/RetrievalController.java)、[SecurityConfig.java](../backend/src/main/java/com/enterprise/compliance/config/SecurityConfig.java)。

## 8 失败、重试与失效

| 情况 | 当前处理 |
| --- | --- |
| 解析未成功 | 索引请求拒绝，先完成正文解析 |
| 索引正在处理 | 重复请求 409，刷新状态 |
| 服务未启用或繁忙 | 503，页面展示错误，可再次查询/索引 |
| HTTP 超时 | 失败或随后租约恢复，不能启用不完整索引 |
| 超过 210 秒租约 | 状态查询/下次请求将运行标记 FAILED，允许重试 |
| 旧响应迟到 | 代次不一致或运行已结束，丢弃 |
| 发布新版本、停用、删除 | 实时 SQL 排除旧键，下次检索不返回 |
| 修改角色/部门范围 | 下一次检索重新授权，无需等待重建 |

Python 向量服务的推理运行在线程中，没有第五阶段解析子进程的硬终止机制。Java 超时后 Python 可能继续算，但没有有效 MySQL 代次的结果无法被查到。

旧向量目前逻辑失效而物理保留，因此可能增加磁盘占用。垃圾回收、消息队列和生产服务端迁移是后续工作；不能把逻辑不可见写成“文件已经删除”。

## 9 如何在项目中使用

1. 按 [AI 服务说明](../ai-service/README.md) 安装完整依赖，执行固定模型准备脚本。
2. 启动 8090 解析进程和 8091 向量进程；配置共享目录、分别独立的内部密钥。
3. Java 开启 PARSER_ENABLED 与 RETRIEVAL_ENABLED。
4. 制度管理上传文件，解析成功后进入“索引管理”，点击“开始索引”。
5. 核对来源后人工发布；员工在“制度原文检索”输入问题。
6. 检查原文、版本、文本块与段落/页码，必要时下载原文件。

项目例子：“出差前需要办理什么手续？”应查到“出差前必须提交审批申请”。页面展示段落来源；不会自动写出“你已经获批”或生成审批决定。

页面入口：[DocumentsView.vue](../frontend/src/views/DocumentsView.vue)、[RetrievalView.vue](../frontend/src/views/RetrievalView.vue)。配置默认关闭检索；验收进程是临时服务，不等于业务环境一直运行。
