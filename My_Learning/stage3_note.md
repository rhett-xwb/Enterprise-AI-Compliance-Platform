# 阶段 3 学习笔记

主题：前端基础、真实登录联调与角色工作空间  
日期：2026年10月12日

这阶段把后端的身份与权限体系接到了用户可以操作的界面上：员工可以登录、进入自己的工作空间、查看有权限的菜单，管理员可以查询真实用户数据。

延续企业办事大厅的类比：阶段 1 建好了档案和办事窗口，阶段 2 建立通行证与岗位权限，阶段 3 为大厅装上入口、导览牌和查询屏。导览牌帮助用户找到窗口，窗口工作人员仍然独立检查通行证和访问资格。

## 1 为什么在认证权限之后开发前端

前端需要知道登录接口如何返回令牌、当前用户有哪些权限，以及失败时应该怎么提示。阶段 2 已经提供这些真实规则，阶段 3 可以直接按接口实现页面。

```text
阶段 1：工程、数据库、用户数据与统一响应
   ↓
阶段 2：登录、JWT、角色权限与数据访问边界
   ↓
阶段 3：登录界面、工作台、菜单、请求和错误处理
   ↓
阶段 4：制度文档上传与版本管理
```

例如，员工登录后没有用户管理入口；即使手动访问用户页面，也会看到无权限提示；直接请求后端用户接口仍返回 403。

**有什么用**：先把各业务页面共同依赖的登录、导航和请求机制做好，后续文档与审批页面可以复用。

**当前边界**：本阶段完成界面基础和真实接口联调。制度、申请、审批、合同页面是明确标记待开放的骨架，不能把出现菜单理解为业务已经完成。

## 2 Vue、Vite、Element Plus、Router 和 Axios 各做什么

前端工程由几个职责不同的工具组成，可以类比后端的框架、启动工具、公共组件和 HTTP 客户端。

| 工具 | 基本概念 | 在本项目中的用途 | 与 Java 后端的类比 |
| --- | --- | --- | --- |
| Vue 3 | 根据数据组织和更新界面的框架 | 登录表单、工作台与用户列表 | 类似框架提供组织代码的基础；浏览器界面职责与 Spring 不同 |
| Vite | 开发服务器与构建工具 | 本地页面服务、API 代理、生成 dist | 开发启动工具与构建工具的组合，不能等同于 Maven |
| Element Plus | 可复用的 Vue 界面组件库 | 表单、按钮、菜单、表格、提示 | 类似复用公共库，减少各模块重复实现 |
| Vue Router | 根据前端地址决定展示哪个页面 | 登录、工作台、权限检查与页面跳转 | 类似 URL 到处理入口的映射，但不会直接执行后端业务 |
| Axios | 浏览器 HTTP 请求客户端 | 调用登录、身份、退出和用户接口 | 类似 Java 的 RestClient，通过 HTTP 访问服务 |

**有什么用**：把页面、导航、网络请求和构建职责分开，知道问题应该在哪一层排查。

**什么时候使用**：新增业务页面时用 Vue 组件组织内容，用 Router 注册入口，用 Element Plus 提供表单和列表，用统一 Axios 客户端调用真实接口。

## 3 Vue 组件与响应式状态

组件是可以独立组织和复用的界面单元。本项目的 `.vue` 文件通常包含 `<script setup>` 和 `<template>`，分别描述页面逻辑和界面结构；公共样式放在 `global.css`。

响应式状态指数据变化后，Vue 自动更新依赖这些数据的界面。`ref` 适合单个状态，`reactive` 适合一组共享数据。

下面是项目采用的基本写法，需要放在 Vue 组件中：

```vue
<script setup>
import { ref } from 'vue'
const busy = ref(false)
</script>

<template>
  <el-button :loading="busy">登录</el-button>
</template>
```

在脚本中设置 `busy.value = true`，按钮会显示加载状态；模板自动读取 ref 的值，不需要手工修改 DOM。DOM 是浏览器中的页面元素结构。

可以类比办事窗口的“正在办理”灯：状态变化，灯自动跟着变化。与普通 Java 字段不同，Vue 的响应式状态会通知界面重新更新。

**有什么用**：登录等待、列表加载、错误提示和身份变化都可以用同一种数据驱动方式表达。

**后续怎么用**：文档上传时维护上传状态，解析任务页面展示处理状态，审批页面展示当前任务信息；业务事实仍来自后端。

## 4 登录为什么要先拿令牌，再获取身份

登录接口验证密码并签发令牌，当前身份接口返回用户、角色与权限。两者回答不同问题：是否允许建立会话，以及这个会话现在能使用哪些功能。

```text
用户输入账号和密码
   ↓
POST /api/auth/login
   ↓
将 accessToken 保存到本标签页的 sessionStorage
   ↓
GET /api/auth/me，携带 Bearer 令牌
   ↓
保存当前身份，进入工作台并生成菜单
```

`sessionStorage` 是浏览器提供的页面会话存储，本项目用它保留当前标签页的令牌。刷新页面时仍可读取；通常关闭标签页后清除。它不是服务端会话表，也不是密码库。

本项目 JWT 没有固化角色权限，所以前端通过 `/auth/me` 获取最新身份，不能从令牌中猜测用户能做什么。密码不持久化，成功进入工作台前还要确认身份查询成功。

**有什么用**：刷新不会立即丢失登录，同时菜单使用后端当前权限。登录成功后身份查询失败，也不会直接进入一个身份不完整的工作台。

**需要注意**：令牌属于敏感凭据，sessionStorage 不是加密保险箱，页面脚本可以读取它。生产部署需要 HTTPS，后续页面开发还要避免把不可信内容作为脚本执行。

## 5 Axios 请求封装与拦截器

请求封装是把各接口共用的配置集中到一个客户端。拦截器是在发送请求前或收到结果后执行的公共处理，可以类比 Spring 的请求过滤器或统一异常处理，但它运行在浏览器中。

本项目在 `src/api/client.js` 中统一配置 `/api` 路径和 15 秒超时，并完成两类处理：

| 位置 | 处理内容 |
| --- | --- |
| 请求拦截器 | 有令牌时添加 `Authorization: Bearer ...` |
| 响应拦截器 | 读取 `{ code, message, data }`；成功返回 data；失败整理用户提示 |

例如，用户列表页面通过公共客户端调用：

```javascript
// 在本项目 Vue 页面中使用，需先导入 api。
const result = await api.get('/users', {
  params: { page: 1, size: 20 },
  quiet: true,
})
// result 包含 records、total、page 和 size。
```

页面不必自己拼完整后端地址、手动添加令牌，或反复读取响应中的 `data.data`。`quiet: true` 是本项目给拦截器使用的自定义配置，表示页面自己展示错误，避免同时出现弹窗和页面提示。

**有什么用**：登录、用户查询及未来文档接口都能复用认证和错误处理规则。

**后续怎么用**：新增接口优先使用这个客户端。页面负责具体加载与重试体验，公共客户端负责认证头和通用异常转换。

## 6 路由守卫与角色菜单

路由守卫是在进入页面之前执行的检查。菜单决定给用户显示哪些入口，守卫检查手动输入地址或页面跳转是否允许。

```text
准备进入页面
   ↓
没有令牌 → 返回登录页
   ↓
重新请求 me → 更新当前身份与权限
   ↓
不满足页面权限 → 进入无访问权限页
   ↓
满足权限 → 展示页面
```

本项目使用 Hash 路由，例如 `/#/users`；`#` 后面的部分由浏览器中的 Router 处理。生产静态服务不需要为每个业务路径单独配置页面回退，但 `/api` 仍需代理到后端。

| 身份 | 当前可见入口 |
| --- | --- |
| EMPLOYEE | 工作台、制度查询、我的申请 |
| LEGAL | 工作台、制度查询、制度管理、我的申请、审批中心、合同审查 |
| ADMIN | 上述入口以及用户管理 |

这张表对应当前种子权限。实际菜单按 `/me` 返回的权限集合生成，支持多角色；用户管理同时要求 ADMIN 和 `user:manage`。

**有什么用**：用户不会被引导到无权使用的页面；角色调整后，下一次页面导航会更新菜单并重新判断资格。

**关键边界**：前端守卫改善操作体验，不能作为最终安全边界。用户可以绕过页面直接发送 HTTP 请求，所以 Spring Security 和资源范围校验仍必须独立执行。

## 7 为什么退出必须调用后端，失败时如何处理

退出需要结束当前会话。本项目调用 `/api/auth/logout` 撤销后端会话，成功后再清除浏览器令牌并返回登录页。

只删除前端令牌相当于扔掉自己的通行证，却没有通知门禁系统。如果别人已经持有副本，后端没有撤销会话时仍可能接受它。

| 情况 | 当前前端行为 |
| --- | --- |
| 后端退出成功 | 清理令牌和身份，进入登录页 |
| 退出请求断网 | 显示错误，保留会话以便重试撤销 |
| 业务请求返回 401 | 清理失效身份，提示重新登录 |
| 恢复身份时暂时断网 | 提示连接失败，允许重试获取身份 |

当前没有刷新令牌机制，到期后重新登录。浏览器会话恢复也需要重新请求后端，不能仅凭本地存在一个字符串就认定登录有效。

**有什么用**：使退出真正影响服务端访问，同时让暂时网络问题有可恢复的路径。

## 8 加载、空数据和错误也是页面功能

页面除了“请求成功且有数据”，还要处理等待、空结果和失败。办事大厅的查询屏也需要告诉员工正在查询、没有记录，还是系统暂时不可用。

| 状态 | 用户列表的表现 |
| --- | --- |
| 正在请求 | 显示加载骨架，避免用户误以为页面没有响应 |
| 查询成功但没有记录 | 显示“暂无用户记录” |
| 请求失败 | 显示错误和“重新加载”按钮 |
| 查询成功且有记录 | 展示表格与分页 |

加载骨架是占位的界面结构，表示数据尚未返回。空数据是成功结果，不能当作服务器错误。

列表使用递增请求编号，只有最后一次发起的请求可以更新当前结果，避免较早请求迟到后覆盖新数据。它可以类比异步 Java 任务回调中先检查“这份结果是否仍然对应当前操作”；这里没有取消已经发送的 HTTP 请求。

**有什么用**：用户能够判断发生了什么，并在网络恢复后继续操作。桌面侧栏和移动端横向菜单也让同一套页面适应不同屏幕。

## 9 本地代理为什么能连接真实后端

开发时前端通常监听 5173，后端监听 8080。端口不同就属于不同源；同源指协议、主机和端口相同。

本项目让浏览器请求前端的 `/api`，Vite 再把它转发到后端：

```text
浏览器：http://127.0.0.1:5173/api/auth/login
   ↓ Vite 开发代理
后端：http://127.0.0.1:8080/api/auth/login
```

类似后端通过网关转发到业务服务：浏览器看到一个入口，代理负责转发，但后端仍检查认证与权限。代理不会伪造业务结果。

**有什么用**：页面可以使用统一相对路径，本地联调无需在各组件写死后端地址。

**怎么用**：按 [前端说明](../frontend/README.md) 启动；后端端口变化时修改 `.env.local` 的 `API_PROXY_TARGET` 并重启 Vite。正式部署使用同源网关和 HTTPS，Vite preview 只用于本地预览。

脚本创建独立验收数据库和服务，结束后停止自身进程。详细环境、结果和限制见 [阶段 3 验收记录](../docs/阶段3验收记录.md)。本次补写笔记没有重新运行这些业务测试。
