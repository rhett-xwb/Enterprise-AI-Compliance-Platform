# 阶段 4：制度文档与版本接口

## 访问规则

所有接口需要有效 Bearer 令牌。JSON 成功返回 `{ code: 0, message, data }`，下载返回原文件字节。

- 管理操作要求 `document:manage`，且用户为制度创建人或拥有 ADMIN 角色。法务不自动获得其他法务制度的管理资格。
- 普通读取要求 `document:read`，角色范围至少命中一个；有部门范围时同时命中部门。未配置部门表示不限制部门，未配置角色拒绝读取。
- 有治理资格的用户可以读取其管理制度的草稿和历史版本，用于检查原文件。
- 普通列表仅返回当前有效制度，详情和下载可以读取曾发布的历史版本，并重新检查最新访问范围；未发布草稿始终不可读。
- 资源不存在、越权或已删除统一返回 404。缺少功能权限为 403，无有效身份为 401。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/documents?management=false&page=1&size=20 | 当前有效、授权制度列表 |
| GET /api/documents?management=true&page=1&size=20 | 可管理制度列表，包含草稿和无当前版本的制度 |
| GET /api/documents/{id} | 制度元数据、角色/部门范围和可读版本，返回 manageable |
| POST /api/documents | Multipart 创建制度及首个文件版本，成功 201 |
| POST /api/documents/{id}/versions | Multipart 上传不可变新版本，成功 201 |
| PUT /api/documents/{id} | 修改名称和访问范围 |
| POST /api/documents/{id}/versions/{versionId}/publish | 发布草稿并停用旧版本 |
| POST /api/documents/{id}/versions/{versionId}/retire | 停用当前发布版本 |
| DELETE /api/documents/{id} | 逻辑删除，禁止访问并保留原文件、版本与审计 |
| GET /api/documents/{id}/audit | 管理人员查看最近 200 条操作记录 |
| GET /api/documents/{id}/versions/{versionId}/file | 重新授权后下载原文件 |

分页 page 为 1–1000000，size 为 1–100。列表不返回文件存储键或服务器路径。版本返回文件名、真实类型、大小、SHA-256、发布/处理状态、生效时间、失效时间、实际发布时间和 searchable（是否当前有效）。

## 上传契约

使用 multipart/form-data，包含 `file` 和 `metadata` 两个 part。`metadata` 的 Content-Type 必须为 application/json；浏览器用 JSON Blob，不能直接把元数据字符串作为 text/plain part。

创建制度的 metadata：

```json
{
  "document": {
    "title": "员工差旅制度",
    "roles": ["EMPLOYEE", "LEGAL", "ADMIN"],
    "departmentIds": []
  },
  "version": {
    "versionNo": "v1.0",
    "effectiveAt": "2026-10-01T00:00:00",
    "expiresAt": null
  }
}
```

上传新版本的 metadata 仅包含上例 version 对象；修改名称和范围使用 JSON document 对象。角色列表至少一项，仅接受 ADMIN、LEGAL、EMPLOYEE。部门编号必须存在；最多 100 项。名称 1–255 字符，版本号 1–32 字符，仅字母、数字、点、下划线、连字符；同一制度内版本号不复用。时间使用北京时间的本地 ISO 格式，失效时间必须晚于生效时间。

支持 PDF、DOCX、PNG、JPG、JPEG，单文件非空且不超过 10 MiB，整请求不超过 11 MiB。旧版 DOC 不支持，需转换成 DOCX。忽略客户端 MIME 声明，按扩展名与实际内容核对后保存规范类型：PDF 检查文件签名，DOCX 检查 ZIP、必需 XML 和正文类型，图片校验类型、尺寸和读取结果。DOCX 解压累计最多 30 MiB、最多 1000 项、禁止路径穿越和 VBA 内容；图片最多 4000 万像素。

此处是上传格式检查，PDF 全文解析质量和 OCR 属于阶段 5；没有将通过签名检查等同于可成功解析。

## 发布、时间与历史

上传创建 DRAFT/PENDING。版本文件、版本号与有效区间没有覆盖修改接口；内容变化必须上传新版本。

发布要求 DRAFT、READY、当前已生效且未过期，并存在文本块，所有块均 INDEXED，文本、vector_key、embedding_model 非空。只有 READY 而没有索引也返回 409。没有手动设置处理就绪的业务接口，未来由阶段 5/6 内部链路维护。

事务锁定逻辑制度行，发布新版本时将旧版设为 RETIRED、旧块设为 INACTIVE，更新当前指针并记录 PUBLISH。重复发布同一当前版本为幂等成功，不增加审计；已停用版本不能重新发布。暂不提供未来版本定时发布：尚未生效返回 409，生效后可再次发布。

停用和逻辑删除清空当前指针并使索引不可见。自然过期在每次有效查询时排除；历史版本仍能在最新授权范围下追溯。未来问答检索必须同时检查当前指针、发布与处理状态、有效时间、索引和 ACL；本阶段不提供问答或向量检索服务。

## 文件存储与审计

FileStorage 将文件读写从业务规则中分离，当前 LocalFileStorage 使用 `DOCUMENT_STORAGE_ROOT`。存储键由服务端随机生成，不使用上传文件名作为磁盘路径；规范化路径与拒绝符号链接，下载检查字节数和 SHA-256，返回 attachment、no-store 和 nosniff。

文件保存后数据库事务回滚时删除本次新增文件。进程在文件写入与事务提交之间崩溃可能留下孤立文件，后续需增加受控清理机制；不承诺文件系统和 MySQL 具有跨资源原子事务。业务删除保留文件，生产备份需同时包含数据库和文件目录。

V4 增加 published_at 和 document_audit，记录 CREATE、UPLOAD、UPDATE_SCOPE、PUBLISH、RETIRE、DELETE 的操作人、时间、关联版本和 JSON 明细。删除后的审计仍在数据库中，当前普通 API 不开放查询；没有新增未经授权的全局审计入口。

常见错误：400 参数/文件格式错误，413 HTTP 文件或请求超限，409 重复版本/发布状态不满足，503 文件缺失、不可读或完整性检查失败。
