## 3 针对性覆盖

| 场景 | 检查 |
| --- | --- |
| 金额分支 | 999.99 单主管，1000 主管后财务；实际配置决定边界 |
| 版本固定 | 发布新版本不改变运行中原路线 |
| RR 快照与并发发布 | 提交事务建立旧快照后发布新定义，当前读取仍选中新发布定义 |
| 配置错误 | 未发布、金额缺口、无权限/停用审批人、自审阻止提交；已提交快照插入回滚 |
| 同意/拒绝/退回 | 顺序处理至终态，拒绝不可重新开启，退回后重新编辑增版本并使预审失效 |
| 撤回重提 | 待办取消，重提保留每次内容快照、实例和历史 |
| 任务归属 | 非处理人无法查看/处理；ADMIN 不能越过任务归属 |
| 资料权限 | 历史审批人看到原提交版本，不能读后来未提交草稿或未分配任务的材料 |
| 失效节点 | 下一审批人权限丢失时保留当前待办并提示配置问题 |
| 重复/并发 | 同意与拒绝、同意与撤回只有一个成功，审计仅一次终态动作 |
| 浏览器闭环 | 管理员发布，法务下载材料/退回，员工重新预审提交，法务同意，申请人查询最终结果与两次实例 |

## 4 本轮修正记录

初次沙箱 TCP 连接失败，MySQL 已就绪但客户端无法连接；改为在沙箱外运行同一隔离验收脚本。首轮新增工作流用例通过，但旧迁移断言仍为 8，以及并发用例新增审批人未清理导致用户计数回归失败；已更新为 9 并清理全部提交、任务、实例、发布与用户夹具。

浏览器审批人下拉框的 placeholder 属于显示层，随后定位到的 combobox 输入又被显示层遮挡；已补充可访问名称，等待审批人目录加载完成后点击实际显示层。键盘操作的尝试未通过，未将其记录为已完成键盘交互验收。代码复核发现提交旧 RR 快照可能无法看见刚发布的定义；定义读取改为 FOR SHARE 当前读取并加入真实 MySQL 时序测试。最终通过状态以第 2 节本轮结果为准。
