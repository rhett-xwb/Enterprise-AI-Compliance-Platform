## 发现与修复

- 旧数据库用例按 V5 计算迁移数量，新增 V6 后修正为六次；最终所有后端用例通过。
- 新检索接口初次联调被原默认拒绝路由规则阻止，补充仅 POST `/api/retrieval/search` 的 document:read 门禁，资源范围继续由方法与 SQL 检查。
- 初次页面用例使用英文关闭按钮和错误确认文字，修正为项目中文“关闭此对话框”和“确认”；停止两轮持续等待的验收 worker 后，由父脚本清理服务并完整重跑。
- 解析详情不再将已索引 READY 版本写回前端 PARSED，成功解析后读取当前版本状态；索引窗口切换管理/查询入口时丢弃旧请求结果。
- 来源下载使用服务端 UTF-8 原文件名，保留 DOCX 扩展名，并纳入浏览器断言。
- 依赖安装/模型下载需要网络与本地进程访问，使用项目专属 venv/cache；全局 Python 未安装项目依赖。Venv 无内置 pip，依照已有方式使用外部 pip --python。

## 边界与后续

向量库使用 Qdrant 本地模式，单进程独占持久目录，索引和查询串行；最多 10000 个授权候选键，超过时明确拒绝。本阶段完成单机检索基础，不承诺生产集群或大数据容量。

旧向量采用实时 MySQL 逻辑失效，未物理删除；索引失败可能保留不可见孤立代次，垃圾回收后续完善。Python ONNX 运算未使用硬超时子进程，Java 超时后可能继续运行，但无法启用失效代次。没有消息队列、自动发布、完整法规/合同模板库、混合检索、重排序、生成答案或问答历史。

索引重建当前替换版本块记录；阶段七保存引用前需要实现被引用块保留策略。未验证已有业务库升级、生产网关、跨主机 TLS、Linux/GPU、压力容量与真实进程崩溃演练。Element Plus 大分块、Java 工具链和既有 Paddle 可选 ccache 提示仍存在。
