# 阶段 2：认证与权限

阶段 2 建立后端认证和数据访问边界。申请创建、流程审批和前端登录界面仍按后续阶段实现。

## 认证接口

所有接口使用 `{ code, message, data }`，成功 `code=0`。HTTP 状态与错误 code 一致。

| 方法与路径 | 输入 / 输出 | 访问条件 |
| --- | --- | --- |
| POST /api/auth/login | JSON：username、password；返回 accessToken、tokenType、expiresIn | 无需令牌 |
| GET /api/auth/me | id、username、departmentId、roles、permissions | 有效令牌 |
| POST /api/auth/logout | 撤销本次登录会话，data=null | 有效令牌 |
| GET /health | data=UP，检查数据库 | 公开 |

登录示例：

```json
{"username":"admin","password":"<本地设置的密码>"}
```

成功响应中的 `tokenType` 为 `Bearer`，`expiresIn` 默认 900（秒）。后续请求头为 `Authorization: Bearer <accessToken>`。未知用户名、错误密码、禁用和已删除账号均返回统一的 401；非法字段返回 400。接口和日志均不返回密码散列。

## 权限矩阵

用户可拥有多个角色，权限为角色权限集合。当前角色定义和种子权限来自 V2。

| 操作 | ADMIN | LEGAL | EMPLOYEE |
| --- | --- | --- | --- |
| 获取自身身份、退出当前登录 | 允许 | 允许 | 允许 |
| 用户列表、详情、创建、修改、删除、分配角色 | 允许且须 user:manage | 拒绝 | 拒绝 |
| 部门详情 | 任意部门 | 本人所属部门 | 本人所属部门 |
| 申请基本信息 | 本人或分配给本人的待办 | 本人或分配给本人的待办 | 本人或分配给本人的待办 |

角色拥有 `document:read/manage`、`contract:review` 等权限不代表对应业务模块已完成；未实现的路径默认拒绝。

用户管理路径：`GET/POST /api/users`、`GET/PUT/DELETE /api/users/{id}`。分页参数 `page` 默认 1、`size` 默认 20 且不超过 100；创建、更新字段沿用 [阶段 1 用户 DTO](./阶段1接口规范.md)。新用户默认 EMPLOYEE。

分配角色：`PUT /api/users/{id}/roles`，请求 `{"roles":["LEGAL"]}`，整体替换角色集合，只接受 ADMIN、LEGAL、EMPLOYEE，集合不得为空。最后一名有效管理员不能被删除、禁用或移除 ADMIN，违反时返回 409；使用数据库锁保护此约束。

`GET /api/departments/{id}` 使用方法权限判断部门范围；越权为 403。`GET /api/approval-requests/{id}` 要求 approval:submit 或 approval:review，并在 SQL 中限制申请人为当前用户，或存在明确分配给当前用户且状态为 PENDING 的审批任务。无权访问和不存在统一返回 404，避免泄露其他申请是否存在。管理员也不自动获得全部申请访问权；待办完成后该授权结束。当前只返回申请基本信息，没有新增审批流。

接口级授权与 `@PreAuthorize` 方法授权同时启用，用户管理同时要求 ADMIN 角色和 user:manage 权限。仅向 LEGAL 增加该权限不能绕过方法角色限制。

## 令牌和会话策略

使用 Spring Security OAuth2 Resource Server 与 Nimbus 实现 HS256 签名及验证。JWT 包含发行者、用户 ID、签发时间、到期时间和会话 UUID，角色与权限不固化在 JWT 中。缺少必要声明、签名错误、发行者错误、到期或没有有效数据库会话均拒绝。

`JWT_SECRET` 必须配置为至少 32 字节随机密钥的 Base64，默认值为空并在启动时拒绝。`JWT_TTL_SECONDS` 默认为 900，范围 60–3600；到期后重新登录，当前没有刷新令牌接口。多个登录会话独立，退出只撤销当前会话。禁用、删除账号会撤销所有会话，重新启用不会恢复旧令牌。每次请求读取当前账号、会话及权限，所以修改角色可作用于下一次请求。已经开始执行的请求不由撤销操作中断。

会话保存在 MySQL，因此使用相同密钥重启服务不会丢失未到期会话。更换签名密钥会使旧令牌失效。过期/撤销记录清理、登录限流和密码重置尚未实现，应在部署及账号管理扩展时补齐。当前不使用 Redis，也没有缓存权限。

认证通过请求头发送，不使用认证 Cookie；无状态 HTTP 配置关闭 CSRF。正式部署使用 HTTPS，后续如引入 Cookie 登录必须调整 CSRF 策略。

## 初始化和核心类

首次部署在无用户的数据库中配置 `INITIAL_ADMIN_ENABLED=true`、`INITIAL_ADMIN_USERNAME` 和 `INITIAL_ADMIN_PASSWORD`。密码至少 12 字符、不超过 72 UTF-8 字节，并以 BCrypt 存储。已有用户时初始化器跳过，重启不会重置密码。首次完成后关闭开关并清除初始密码环境变量；现有阶段 1 账号不会自动升级为管理员。参见 [后端启动说明](../backend/README.md)。

| 类 | 职责 |
| --- | --- |
| SecurityConfig | 两条独立安全过滤链、URL 权限、统一 401/403、方法权限开关 |
| JwtConfig | 签名密钥校验、编码器/解码器和声明校验 |
| AuthService | 密码校验、创建登录会话、加载当前身份权限、撤销会话 |
| AuthController | 登录、当前身份、退出接口 |
| PlatformPrincipal | 本次请求的用户身份、部门、角色、权限与会话 ID |
| InitialAdminRunner | 仅空用户库首次建立管理员，不覆盖已有账号 |
| AdminUserController | ADMIN 用户管理与角色分配 |
| ResourceAccess / ScopedResourceController | 部门范围判断与申请查询范围限制 |

原 `/api/bootstrap/users` Basic 接口保留供阶段 1 回归验证，默认关闭且只能监听回环地址；其临时内存账号不能用于正式 Bearer 接口。
