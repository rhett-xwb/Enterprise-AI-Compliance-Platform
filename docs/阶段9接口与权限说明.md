# 阶段九：可配置人工审批

日期：2026年10月12日。适用范围：人民币差旅申请、有序单人节点、金额区间分支。

## 1 选型与发布

实现前比较了两条路线：Flowable 支持 BPMN、并行/会签、图形建模与复杂流程治理，但会增加引擎依赖、部署和业务身份映射；有限方案复用现有 MySQL 表和 Spring 事务，可覆盖当前金额分支及顺序单人节点，范围清晰且更容易验收。本阶段选择有限方案，不提供 BPMN、会签、并行、代理、任务转派、自动审批和运行实例迁移。需要这些能力时重新评估 Flowable。

管理员在“审批流程配置”选择审批人、填写金额区间与节点，再发布。新版本立即成为新提交使用的版本，历史版本不可编辑。发布需 ADMIN；不赋予管理员绕过任务归属审批的能力。审批人必须启用、未删除并拥有 approval:review。流程不默认创建，缺配置阻止提交。

区间 `[minimum,maximum)`，最后 maximum=null；必须从零开始连续覆盖、不重叠。最多 20 个区间，每区间 1–10 个节点。节点 name 最多 100 字，金额最多 16 位整数与 2 位小数。示例金额不是业务制度。

```json
{
  "name": "差旅审批",
  "routes": [
    {"minimum": 0, "maximum": 1000, "nodes": [{"name": "主管", "assigneeId": 12}]},
    {"minimum": 1000, "maximum": null, "nodes": [{"name": "主管", "assigneeId": 12}, {"name": "财务", "assigneeId": 18}]}
  ]
}
```

## 2 API

全部接口使用 JWT，返回统一 ApiResponse。以下前缀为 `/api/workflows`。

| 方法/路径 | 权限与用途 |
| --- | --- |
| GET /definitions | ADMIN，最近 50 个发布版本及当前标记 |
| GET /assignees | ADMIN，当前可选审批人 |
| POST /definitions | ADMIN，上述配置生成新版本 |
| GET /tasks?before=...&size=20&history=false | approval:review，仅本人待办；history=true 查询本人已处理/取消任务；size 1–50 |
| GET /tasks/{id} | approval:review，仅任务处理人，提交快照及历史 |
| POST /tasks/{id}/decisions | approval:review，仅处理人；`{"lockVersion":1,"action":"APPROVE","opinion":"核对完成"}` |
| GET /requests/{id}/materials | approval:review，仅实际收到任务的审批人，所分配最新提交快照的材料和关联预审 |
| GET /requests/{id}/attachments/{attachmentId} | approval:review，附件必须属于本人任务对应的提交快照；私有下载，no-store |
| GET /requests/{id}/history | approval:submit 或 approval:review，仅申请人或历史任务参与人 |
| POST /requests/{id}/withdraw | approval:submit，仅申请人，`{"contentVersion":1}` |
| POST /requests/{id}/reopen | approval:submit，仅申请人，`{"contentVersion":1}` |

Decision.action 仅 APPROVE、REJECT、RETURN，opinion 必填、最多 3000 字。lockVersion 初始 1，每次处理/取消增加 1。过期或重复请求返回 409；他人任务与资料返回 404；缺功能权限返回 403。任务详情的 request_snapshot 是 JSON 字符串，前端解析后按纯文本渲染。

预审依据仍应用当前阅读者的制度权限：任何来源不可访问时隐藏整段建议与证据。审批授权不自动授予制度访问权。资料接口只返回实际收到的提交版本，不暴露退回后未提交的新草稿；附件软移除后仍可在获分配的历史快照中下载。

## 3 状态与事务

```text
DRAFT --提交/预审/配置校验--> IN_REVIEW
IN_REVIEW --APPROVE--> 下一节点 IN_REVIEW / 最后节点 APPROVED
IN_REVIEW --REJECT--> REJECTED
IN_REVIEW --RETURN--> RETURNED
IN_REVIEW / 历史 SUBMITTED --本人撤回--> WITHDRAWN
RETURNED / WITHDRAWN --本人重新编辑--> DRAFT（内容版本 +1，预审 STALE）
```

提交同事务保存 request_submission、SUBMIT、固定流程版本/金额路线/材料快照、首个 PENDING 和 START。SUBMITTED 是提交审计中的中间状态，新接口成功提交直接返回 IN_REVIEW。AI 风险独立保存，不驱动人工结果。APPROVED/REJECTED 本阶段不重新开启。

发布和提交使用 workflow_publication 的单行锁，串行选择/分配版本。任务处理、撤回、重新编辑先锁申请行，再锁任务行；状态/任务归属/版本检查、后续任务、申请状态与审计都在同一事务。唯一约束保证同内容版本只有一份提交及一实例，同实例节点只创建一次。重复操作返回冲突，不产生第二次流转。

启动检查整条路线的审批人资格与禁止自审；向下一节点流转时再次检查资格。审批人后续停用会提示配置问题并保留当前待办，恢复账号/权限后重试；本阶段无任务转派接口。

## 4 V9 兼容与边界

V1–V8 保留，V9 增加 workflow_publication、route_json、node_index 与唯一约束；request_submission 从 request_id 唯一扩为 (request_id,content_version) 唯一，以保留重提历史。

升级前的 SUBMITTED 不自动选择新流程，避免把新配置当作旧时决定。本人可撤回后重新编辑、预审、提交进入已发布流程。历史预留引擎实例不自动转换。已发布版本列表最多 50 条，任务列表支持游标；材料页面使用有限预审历史，超过窗口的老预审展示限制待完善。审批人目录和单笔操作历史尚未分页。
