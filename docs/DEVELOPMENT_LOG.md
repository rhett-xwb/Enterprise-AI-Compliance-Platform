# 开发日志

项目：Enterprise AI Compliance Platform（企业智能法律合规与审批平台）

本日志记录项目的重要设计决策、功能实现、架构调整、关键缺陷修复与交付验证。重大改动完成时，在同一次工作中同步更新本文件，使后续开发能够了解改动原因、实际结果与未完成事项。

## 维护规则

- 按日期倒序记录，同一天的多条记录以标题区分。日期使用 Asia/Shanghai 时区。
- 新增或调整业务模块、权限规则、数据库结构、接口契约、文档版本规则、AI 检索与分析流程、审批流程、依赖及部署方式时，必须更新日志。
- 影响数据一致性、权限隔离或核心业务行为的缺陷修复，以及重要的设计文件交付，也应记录。
- 同一任务中的小幅调整合并为一条；普通格式整理无需单独记录，除非影响使用或交付。
- 记录实际发生的改动。将已完成、待验证、待决定和后续计划明确区分，不将规划写成已实现功能。
- 验证部分填写实际执行的检查与结果；没有运行检查时说明原因，不写“测试通过”。
- 不记录密码、访问令牌、真实企业敏感资料或个人敏感信息。
- 已有记录保留；如发现错误，以更正说明补充，不静默改写历史结果。

## 记录模板

```markdown
### YYYY-MM-DD 变更标题

- 类型：设计 / 功能 / 修复 / 架构 / 部署 / 文档
- 状态：已完成 / 部分完成 / 待验证
- 背景与目的：为什么需要这次改动。
- 实际改动：完成了哪些内容，涉及哪些文件或模块。
- 影响与兼容性：对接口、数据、权限和运行方式的影响；如适用，说明迁移与回退方式。
- 验证：执行的检查、结果及没有覆盖的范围。
- 遗留事项：尚未完成的工作、已知限制与待决定事项；没有则填写“无”。
```
