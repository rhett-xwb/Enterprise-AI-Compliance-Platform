# 阶段 6 接口与权限说明

日期：2026年10月12日。范围为企业制度（POLICY）原文检索，生成答案与问答历史属于阶段七。

## 技术边界

Java 负责切片、索引运行状态、MySQL 文本块、版本发布与实时授权。独立 FastAPI 进程负责 FastEmbed 中文向量和 Qdrant 本地持久化，不查询用户库。选型使用 Qdrant Client 1.19.1、FastEmbed 0.8.1、ONNX Runtime 1.31.0；模型 `BAAI/bge-small-zh-v1.5`，512 维、Cosine；固定公开快照 `46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59`。

不引入额外 RAG 编排框架，采用 Java 调用内部索引/检索 HTTP 契约；阶段七的生成模型和编排框架仍待确定。向量库可以重建，MySQL 是来源与业务事实的权威存储。

## 业务接口

全部使用 Bearer JWT 与统一响应结构。

| 方法与地址 | 权限 | 行为 |
| --- | --- | --- |
| GET `/api/documents/{id}/versions/{versionId}/index` | document:manage + 本人治理/ADMIN | 返回索引运行状态，未发起返回 null；超过租约的运行标记 FAILED |
| POST 同上，`?rebuild=false` | 同上 | 解析成功后切片并同步建立真实索引；已成功时默认复用当前代次 |
| POST 同上，`?rebuild=true` | 同上 | 建立新代次，处理中暂停该版本检索，成功后原子启用 |
| POST `/api/retrieval/search` | document:read + 实时角色/部门范围 | 仅返回授权、当前已发布且有效的 POLICY 原文 |

查询请求：

```json
{"query":"出差前要办理什么手续？","topK":5,"minScore":0.5}
```

`query` 为 1–500 字符非空问题，`topK` 1–20，`minScore` 0–1。页面固定使用 topK=5/minScore=0.5；该分数是模型相似度，不是答案正确概率。没有匹配结果返回空数组，不推测答案。

命中字段：documentId、documentVersionId、chunkId、title、versionNo、pageNumber、sectionTitle、location、sourceIndex、startOffset、endOffset、text、score。正文从 MySQL 的实际有效文本块组装，不能信任向量库提供的正文或 ACL。偏移基于 Java UTF-16 `[startOffset,endOffset)`；Word 页码为 null，位置为真实段落/来源。来源下载继续使用阶段四文件接口，并重新校验权限。

索引状态：status、attempts、errorCode、generation、embeddingModel。成功不是发布；法务仍须核对正文后手动发布。正文源已成功解析，DRAFT/PUBLISHED 版本可建立/重建；处理中重复请求返回 409。版本停用后不能重建。

## 切片、原子启用与恢复

按每个来源内标题、章节和条款起始分段。每块最多 400 个 Java 字符；长条款优先在句末/换行截断，重叠 60 字符；跨条款、PDF 页或 DOCX 段落不制造混合来源。保留原文，不声称完成复杂语义章节重建。

```text
PARSED + 解析成功来源
→ 锁定制度 → 创建索引代次 → 向量写入
→ 校验代次/模型/全部键 → MySQL 原子写入文本块 + READY
→ 人工核对 → 发布 → 授权原文检索
```

向量键由 Java 生成 UUID。内部相同代次 upsert 幂等，重复业务请求复用成功运行；重建产生新代次，旧代次/迟到响应不能覆盖当前状态。数据库完成前向量不会进入候选。失败保留 PARSED，旧文本块 INACTIVE，手动重试建立新代次。索引 HTTP 超时 180 秒、租约 210 秒，状态刷新和后续请求恢复过期运行。

Java 校验内部结果的模型、代次、所有键与数量；搜索校验键属于已授权集合、分数有限、条数和重复键。异常返回 503，不生成假索引。被删除/停用的文档即使收到迟到结果也不会启用。

## 权限与失效

1. 实时查询当前用户角色关联和数据库部门，筛选 currentVersionId、PUBLISHED、READY、生效/未过期、所有块 INDEXED、成功索引代次与模型匹配；管理员检索也遵守范围，不使用治理特权绕过检索 ACL。
2. 授权向量键传给 Qdrant，以 HasIdCondition 过滤后排序，避免未授权高分项占满 topK。
3. 内部调用结束后，在新数据库事务里再执行相同过滤，并取实际正文；权限、部门、版本、到期或删除变化会排除已经不适用的命中。

发布新版本、停用、软删除及修改范围沿用阶段四事务与权限规则，无需等待向量清理即可逻辑失效；文档日期过滤实时生效。已在浏览器展示的历史内容不会被服务端主动擦除，下次查询/下载重新授权。

## 内部契约与运行限制

FastAPI 8091，仅内部调用。`X-Retrieval-Secret` 是至少 32 字符独立密钥，启动必须配置。`POST /internal/index` 接收 documentId、documentVersionId、generation、roles、departmentIds 和 chunks；每块包含 key/text/sourceIndex/pageNumber/location/sectionTitle，向量 payload 另存 POLICY 与模型。范围是索引时快照，权限以 MySQL 为准。`POST /internal/search` 接收 query/keys/topK/minScore，仅返回 model 与 hits(key/score)。额外字段拒绝。

默认 `RETRIEVAL_ENABLED=false`。启动方法和固定模型准备见 [AI 服务说明](../ai-service/README.md)。本地持久目录只允许一个进程、一个 worker，索引和检索共用互斥锁；忙碌返回内部 429、业务 503。每次最多 10000 块和 10000 个授权候选键，超过候选容量明确拒绝，不静默截断。

失效采用逻辑过滤，旧向量物理回收尚未实现；运行失败可能留下孤立代次。Python ONNX 运算没有硬终止子进程，Java 超时后可能继续运行，但无有效 MySQL 代次的向量不可见。生产 Qdrant 服务端、批量分页索引、任务队列、垃圾回收、法律法规和合同模板库、混合检索/重排序及大规模性能验证后续完善。
