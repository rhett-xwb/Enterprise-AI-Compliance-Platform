# 阶段 1 接口规范

基础地址默认为 `http://127.0.0.1:8080`。正式登录与 JWT 尚未实现。除 `/health` 外，接口默认拒绝访问；仅在显式开启本地临时 CRUD 模式时，内存管理员通过 HTTP Basic 访问用户接口。

## 响应与错误

所有已实现 API 的响应使用 `code`、`message` 和 `data`：

```json
{"code":0,"message":"success","data":{}}
```

成功 `code=0`；错误 `code` 与 HTTP 状态码一致，`data=null`。错误不回显请求值、数据库 SQL、堆栈或密码。每个请求返回服务端生成的 `X-Request-Id`，日志仅记录请求标识、方法、状态和耗时，不记录认证头或请求正文。

| HTTP 状态 | 含义 |
| --- | --- |
| 200 | 查询、更新、删除成功 |
| 201 | 用户创建成功 |
| 400 | 参数、JSON、未知字段或部门标识无效 |
| 401 | 未认证或凭据错误，默认关闭接口时匿名访问亦被拒绝 |
| 403 | 已认证但无权限；关闭模式下即使具有临时管理员身份也不能访问 |
| 404 | 用户不存在或已删除 |
| 409 | 用户名或关联数据冲突 |
| 405 / 415 | 请求方法或媒体类型不支持 |
| 500 / 503 | 内部错误 / 健康检查发现数据库不可用 |

## 健康检查

`GET /health` 无需认证，仅返回数据库是否可连接，不暴露连接参数。

```json
{"code":0,"message":"success","data":"UP"}
```

## 用户 CRUD

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/bootstrap/users` | 新增用户，并关联 EMPLOYEE 角色 |
| GET | `/api/bootstrap/users?page=1&size=20` | 分页查询未删除用户 |
| GET | `/api/bootstrap/users/{id}` | 查询用户详情 |
| PUT | `/api/bootstrap/users/{id}` | 更新展示名称、邮箱、部门和启用状态 |
| DELETE | `/api/bootstrap/users/{id}` | 软删除、禁用并清除角色关联 |

用户 ID 必须为正数。页码范围 1–1000000，页大小范围 1–100，列表按 ID 倒序。新增用户名限定为 3–64 位字母、数字、下划线或连字符。用户名唯一且删除后仍保留，不回收重用。

### 创建请求

```json
{
  "username":"employee_demo",
  "password":"example-password-only",
  "displayName":"演示员工",
  "email":"employee@example.test",
  "departmentId":null
}
```

密码至少 12 字符、最多 72 字符且不超过 72 UTF-8 字节；仅以 BCrypt 散列保存。展示名称必填且不超过 100 字符，邮箱可为空，非空时必须是有效邮箱且不超过 254 字符。部门可为空，非空时必须存在。未知字段被拒绝，不能通过传入 `role` 或 `passwordHash` 绕过服务端设置。

### 用户返回字段

```json
{
  "code":0,
  "message":"success",
  "data":{
    "id":1,
    "username":"employee_demo",
    "displayName":"演示员工",
    "email":"employee@example.test",
    "departmentId":null,
    "enabled":true,
    "createdAt":"2026-10-11T22:00:00",
    "updatedAt":"2026-10-11T22:00:00"
  }
}
```

响应 DTO 不包含明文密码或密码散列。记录时间使用应用本地时区，运行环境应设置为 Asia/Shanghai；示例数据不是实际账号。

### 更新请求

```json
{"displayName":"更新员工","email":null,"departmentId":null,"enabled":false}
```

PUT 替换这四个可更新字段；`displayName` 与 `enabled` 必填，邮箱和部门为 null 时清空。此接口不能修改用户名、密码或角色。

### 分页返回与删除

列表的 `data` 包含 `page`、`size`、`total` 与 `records`。删除返回 `{"code":0,"message":"success","data":null}`。软删除后的用户不出现在列表，详情返回 404；重复删除返回 404。保留用户记录以支持未来历史审计。

## 认证模式与下一阶段

临时账号由环境变量设置，不写入数据库，不提供公开注册或登录接口。HTTP Basic 仅在回环监听且显式开启的开发模式下使用。阶段 2 将接入企业账号密码认证、JWT 和正式 RBAC；不得将临时管理员认证解释为已完成该阶段。
