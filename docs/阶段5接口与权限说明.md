# 阶段 5 文档解析接口与权限

日期：2026年10月12日

## 1 业务接口

全部使用阶段二 Bearer 认证，要求 document:manage，且为制度创建人或 ADMIN。同角色其他法务不能管理或读取该草稿正文；非管理者不得使用解析来源接口。删除制度和版本归属不匹配返回 404。

| 方法与路径 | 行为 |
| --- | --- |
| POST /api/documents/{id}/versions/{versionId}/parse | 202，创建或复用任务；服务未启用返回 503 |
| POST 同一路径 ?retry=true | 失败后重试同一个任务；最多五次尝试 |
| GET 同一路径 | 查询任务，尚未创建时 data=null |
| GET /api/documents/{id}/versions/{versionId}/sources | 管理者查看解析来源，失败或尚未完成时空数组 |

解析为法务主动操作；上传不会自动提交解析任务。启动需开启 PARSER_ENABLED，默认关闭。重试只适用于 FAILED，成功和进行中的重复请求返回原任务；原文件不可变，修正内容应上传新版本。

任务数据：id、documentVersionId、status、attempts、errorCode、parserVersion。公开结果不包含存储路径、内部密钥或运行令牌。来源包含 sourceIndex（从 0 开始）、pageNumber、location、sectionTitle、text、method、confidence、warnings。

## 2 Java 到 Python 内部契约

POST /internal/parse，Content-Type: application/json，X-Parser-Secret 为共享随机密钥。Python 必须与 Java 使用相同的私有原文件存储目录，只接受服务器 UUID.bin 键，不允许路径、URL 或联网获取原文件。

```json
{
  "documentVersionId": 42,
  "taskId": 12,
  "storageKey": "12345678-1234-1234-1234-123456789abc.bin",
  "contentSha256": "64位小写十六进制摘要（示意值）",
  "contentType": "application/pdf",
  "sizeBytes": 12345
}
```

成功返回 200，字段 taskId、documentVersionId、contentSha256、parserVersion 和 pages。pages 每项与业务来源字段对应。

```json
{
  "sourceIndex": 0,
  "pageNumber": 1,
  "location": "第 1 页",
  "sectionTitle": null,
  "text": "差旅报销须提交审批",
  "method": "TEXT",
  "confidence": null,
  "warnings": []
}
```

PDF/图片 pageNumber 从 1 开始；DOCX 为 null，以真实段落顺序和可识别的 Heading 样式保留章节。DOCX 不声称有固定页码。TEXT 为电子 PDF 文本，OCR 为模型识别，DOCX 为 Word 段落。OCR 平均置信度不足 0.85 时 LOW_CONFIDENCE；空页 EMPTY_SOURCE。正文按普通文本渲染，不能执行其中 HTML 或脚本。

电子 PDF 只要存在可提取正文（包括短正文）就优先保留；无文字层的页才 OCR。含文字水印与扫描图混排的页面尚未按区域同时提取，应人工核对。

Python 不向 MySQL 写入，Java 核对返回任务、版本、摘要、来源连续性和大小，随后在同一事务内保存来源和成功状态。版本使用 PARSED（已解析、待索引），不会创建 document_chunk 或将其伪造为 INDEXED/READY。阶段六才能接入切片和真实向量索引。

## 3 状态、重试与恢复

```text
首次提交 → PENDING → PROCESSING → SUCCEEDED（版本 PARSED）
                           └──→ FAILED（版本 FAILED）
                                  ↓ retry=true
                                PENDING
```

任务键 parse:{versionId} 唯一。attempts 在领取时加一，不因重复 POST 增加。文档行锁串行化同一制度的解析请求、删除和发布；每次运行生成 run_token 和 lease_until。崩溃遗留 PROCESSING 在下一次调度发现租约过期后标记 WORKER_TIMEOUT。新一轮重试生成新令牌，旧回包无法写入。

同一 Java 实例每次处理一个任务，多实例通过数据库状态与锁防止重复领取；Python 有独立容量限制，忙碌返回明确失败码。队列达到 100 个待处理/执行中任务时拒绝新提交，该计数是准入检查，跨文档并发下不是集群严格配额。未启用 Java worker 时不消费任务。成功任务不开放强制重新解析；改动解析策略时可在后续提供受控重建入口。

## 4 失败与资源限制

Python 401 表示内部认证失败；429 为并发已满；504 为硬超时；422 为明确解析失败或输入结构不合法。已知解析错误通过 detail.errorCode 返回，Java 白名单映射；异常不返回原文件路径、底层栈或正文。

| 错误码 | 含义 |
| --- | --- |
| FILE_REFERENCE_INVALID / FILE_UNAVAILABLE | 文件引用不合法或文件不可用 |
| FILE_INTEGRITY | 字节数或 SHA-256 不匹配 |
| FILE_SIZE_LIMIT / PAGE_LIMIT / IMAGE_LIMIT | 文件、PDF 页数或图片像素超过限制 |
| ARCHIVE_LIMIT / SOURCE_LIMIT / TEXT_LIMIT | Word 解压、段落数或文本量超限 |
| PDF_ENCRYPTED / UNSUPPORTED_TYPE | 加密 PDF 或格式不支持 |
| EMPTY_DOCUMENT / PARSE_FAILED / PARSER_CRASH | 无文字、损坏文件或子进程异常 |
| PARSER_BUSY / PARSE_TIMEOUT | 内部容量满或解析超时 |
| PARSER_NOT_CONFIGURED / PARSER_UNAVAILABLE | Java 未配置密钥或内部调用不可用 |
| PARSER_RESPONSE_INVALID | 响应身份、结构或正文校验失败 |
| WORKER_TIMEOUT / WORKER_INTERRUPTED | Java 任务租约过期或线程中断 |
| DOCUMENT_DELETED | 执行期间制度被删除，结果丢弃 |

默认：10 MiB/100 页/4000 万像素；DOCX 最多 30 MiB 解压和 1000 ZIP 项，最多 2000 非空段落；每来源 10 万字符，总计 200 万；Python 单实例一个并发、180 秒；Java 190 秒请求超时、最大 12 MiB 响应，超过租约必须重试。

V5 增加 PARSED 状态、任务令牌/租约/解析器版本字段及 document_parse_source 表，保留 V1–V4 历史迁移。解析失败不留下部分正文；删除保留历史已保存正文但业务接口禁止访问。停止 worker 后，活跃任务可能待租约过期才能重试。尚未引入 RabbitMQ、Redis、复杂版面坐标、人工纠错保存或文档预览器；人工核对入口为来源正文与授权原文件下载。
